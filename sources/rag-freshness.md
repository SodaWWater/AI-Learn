# RAG 知识时效与更新策略

RAG 的基础原理相对稳定，但模型、框架、托管 API、评测工具和高级范式变化很快。仓库不使用“永久最新”这类无法验证的表述，而是记录每条变化内容的审核时间和适用版本。

## 时效等级

| 等级 | 内容 | 最长复核间隔 |
|---|---|---:|
| `volatile` | 商业 API、模型名称、价格、参数限制、框架接口 | 30 天 |
| `active` | 高级 RAG 范式、工具选型、生产最佳实践 | 90 天 |
| `research` | 新论文、基准、实验结论 | 180 天 |
| `stable` | 经典检索、索引、相似度和基础架构原理 | 365 天 |

## 来源优先级

1. 官方文档、官方代码仓库和原始论文。
2. 有实验设计、数据和代码的技术报告。
3. 公开第一人称面经，仅证明“有人被问过”，不证明答案正确。
4. 二次题库、博客和汇总仓库只用于发现线索，技术结论必须回到一手资料核验。

## 更新动作

- 记录 `reviewed_at`、版本或 Commit、适用范围和替代方案。
- 新资料先进入来源盘点和差异审计，不直接覆盖旧结论。
- 旧结论失效时保留版本关系，标记 `superseded`，不静默删除历史。
- 每次正式发布前检查超过复核期限的 `volatile` 和 `active` 内容。
