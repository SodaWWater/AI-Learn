# RAG 学习启动页

本页用于开始学习，不替代来源审计。当前版本是范围受限正式发布（Bounded Formal Release）：13 个模块、189 个有来源知识原子已经通过严格验收；2 个无来源库存占位不作为结论。

## 开始前

建议具备：

- Python 基础和基本的数据结构、网络请求与日志阅读能力；
- 对大语言模型（Large Language Model，LLM）和提示词（Prompt）有基本认识；
- 能阅读 Markdown、JSON 和简单的服务配置。

不需要先安装特定向量数据库（Vector Database）或模型。先理解流程，再在章节的“具体技术或框架实现”中选择组件。

## 推荐顺序

1. 阅读[学习总览](overview.md)和[完整 RAG 流程](rag-workflow.md)，先建立离线建库、在线问答、评估反馈和生产治理四条主干。
2. 按 `RAG-01` → `RAG-06` 学习基础、架构、解析、文本切分（Chunking）、向量嵌入（Embedding）和存储索引，形成可运行的离线链路。
3. 按 `RAG-07` → `RAG-09` 学习查询理解、检索融合重排、上下文组装和答案生成，形成在线问答链路。
4. 学习 `RAG-10` 和 `RAG-11`，为检索质量、答案质量、延迟、成本、安全和可观测性建立验证与治理闭环。
5. 学习 `RAG-12` 的高级检索增强生成（Advanced RAG）范式，再阅读 `RAG-13` 的项目与面试应用。
6. 每个模块先看关系图，再读四段式章节；遇到工程现象时进入对应问题库存，沿问题的节点、根因、方案和验证关系回查正文。

## 每个模块的完成标准

- 能说明该模块的输入、输出、关键假设和失败边界；
- 能在 RAG 流程中指出实际开发位置，并说出至少一种实现方式；
- 能使用模块关系图定位上下游节点和相关工程问题；
- 能用一个离线或在线指标验证改动，而不是只描述主观效果。

## 当前边界

- `RAG-07-001` 与 `RAG-13-011` 是 `inventory_draft` 占位，尚无来源，不要把它们当作已验证知识。
- 产品和框架应用程序编程接口（Application Programming Interface，API）属于动态内容，应按[动态版本审计](../../audits/rag/dynamic-version-audit.md)的审核日期复核。
- 新的外部搜索已暂停；如需扩展来源或补齐占位，先获得用户授权并建立新的工作包。

完成一轮学习后，使用[章节问题链接审计](../../audits/rag/chapter-problem-links.md)和[发布验收报告](../../audits/rag/p8-strict-acceptance.md)检查覆盖边界，再针对薄弱节点回到对应局部图。
