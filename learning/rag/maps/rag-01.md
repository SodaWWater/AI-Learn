# RAG-01 基础与边界：关系图

> 本模块回答三个问题：为什么需要 RAG、RAG 与相邻方案是什么关系、什么时候不应默认选择 RAG。

## 图 1：问题、机制与能力边界

```mermaid
flowchart TD
    K1["01-002 知识截止、空白与更新"] -->|促使引入外部知识| D["01-001 RAG 定义与目标"]
    K2["01-003 私域接入与可审计"] -->|提出来源与权限要求| D
    D -->|用检索证据约束生成| H["01-004 缓解幻觉"]
    H -->|不能保证检索正确或模型忠实| B["能力边界"]
    B -->|需要分层评估| E["RAG-10 评估"]
    B -->|需要拒答、核查和引用| G["RAG-09 上下文与生成"]
```

核心关系是“缓解”而不是“消灭”：RAG 增加了可检查的非参数知识通道，却同时引入解析、切分、召回、排序、上下文组装和生成忠实度等新的故障点。

## 图 2：RAG 与相邻技术的关系

```mermaid
flowchart TD
    R["01-001 RAG"] -->|推理时检索非参数知识| X["外部证据上下文"]
    F["01-005 微调"] -->|训练时更新参数或行为| P["参数化能力与行为"]
    L["01-006 长上下文"] -->|一次装入更多原文| X
    S["01-007 传统搜索"] -->|返回文档或排序结果| X
    M["01-008 模型记忆与上下文工程"] -->|组织短期、长期和工具状态| X

    R <-->|知识与行为可组合| F
    R <-->|按任务、长度和成本路由| L
    R -->|复用召回与排序能力| S
    R -->|可作为长期记忆读取机制| M
```

这些概念不处于同一维度：微调改变模型参数或行为；长上下文描述输入容量；传统搜索关注信息检索；记忆/上下文工程管理信息何时写入、读取和组装。它们都可能与 RAG 组合。

## 图 3：适用性决策关系

```mermaid
flowchart TD
    N["待解决任务"] --> C1{"知识是否外部且会变化？"}
    C1 -->|是| C2{"需要来源、权限或可删除性？"}
    C1 -->|否| C3{"主要问题是行为或格式吗？"}
    C2 -->|是| Y["01-009 RAG 高适配"]
    C2 -->|否| C4{"语料是否可检索且答案有证据？"}
    C4 -->|是| Y
    C4 -->|否| N1["01-010 RAG 收益有限"]
    C3 -->|是| F["01-005 优先提示或微调"]
    C3 -->|否| C5{"少量原文能否稳定装入上下文？"}
    C5 -->|是| L["01-006 长上下文或直接上下文"]
    C5 -->|否| N1
    Y -->|仍须用业务集验证| E["RAG-10 评估"]
```

## 原子知识覆盖

| 原子 ID | 在图中的角色 | 主要关系 |
|---|---|---|
| RAG-01-001 | RAG 定义与目标 | 由知识问题触发，产生外部证据上下文 |
| RAG-01-002 | 知识截止、空白、更新 | `促使引入` RAG |
| RAG-01-003 | 私域与审计 | `约束` 来源、权限与追踪 |
| RAG-01-004 | 幻觉缓解与边界 | RAG `改进但不保证` 忠实性 |
| RAG-01-005 | RAG 与微调 | `替代或组合` |
| RAG-01-006 | RAG 与长上下文 | `路由、替代或组合` |
| RAG-01-007 | RAG 与传统搜索 | RAG `复用并扩展` 搜索 |
| RAG-01-008 | RAG 与记忆、上下文工程 | RAG `实现` 部分长期记忆读取 |
| RAG-01-009 | 适合 RAG 的条件 | 由适用性判断 `选择` |
| RAG-01-010 | 不适合或收益有限 | 由边界条件 `排除` |

覆盖：**10 / 10**。详细解释见[标准学习正文](../../../knowledge/rag/chapters/rag-01-foundations.md)。
