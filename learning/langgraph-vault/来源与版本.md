## 当前版本需要特别防止的旧知识

2026-09-16 官方文档明确：

- `langgraph.prebuilt.create_react_agent` 已 deprecated，当前高层入口推荐 `langchain.agents.create_agent`；
- `MessageGraph` 已 deprecated，使用 `StateGraph` + `messages`；
- LangGraph v1 的核心 Graph primitives（State、Nodes、Edges）和 Runtime execution model 保持稳定；
- Python 3.9 支持已经移除。

因此第三方题库如果仍把旧 API 当“当前最佳实践”，只把它当成题目线索，答案必须重新核验。

## Part 4 M01～M03 特别核对

- LangGraph 当前官方定位是 low-level orchestration framework and runtime，重点包括 durable execution、streaming、human-in-the-loop、persistence，并允许 deterministic steps 与 agentic steps 混合。
- 当前官方建议：常见 Agent Loop 优先考虑 LangChain `create_agent`；需要更细粒度 orchestration 时使用 LangGraph。
- `ToolNode` 是用于执行 Tools 的预构建 LangGraph Node；Tool 与 ToolNode 不是同一个概念。
- Workflow 路径预先定义，Agent 动态决定过程和工具使用；生产系统可以把两者混合在同一 Graph。
- Subgraph 是 Graph composition，不等于子 Agent。Parent / Subgraph State Schema 不同的时候，可以通过 Wrapper Node 做输入输出转换。
- 当前 Multi-Agent 官方文档明确提醒：不是所有复杂任务都需要 Multi-Agent，Single Agent + 合适的 Tools 很多时候已经足够；Multi-Agent 的主要动机包括 Context Management、Distributed Development、Parallelization 等，同时会增加 Model Call / Token / Coordination 成本。
