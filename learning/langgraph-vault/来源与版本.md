## Part 3 特别核对的当前 API 事实

- `StateGraph` 是 Graph API 主要图类；先定义 State，再添加 Node / Edge，最后 `compile()`。
- Node 可以返回部分 State Update，不需要返回完整 State。
- 每个 State key 独立拥有 reducer；未显式指定 reducer 时，新值默认覆盖旧值。
- `Annotated[list[T], operator.add]` 是常见的列表累积 reducer 写法。
- `add_conditional_edges()` 可以根据当前 State 路由到不同 Node，也可路由到多个目标。
- `Command` 适合在 Node 内同时表达 State Update 和 `goto` 等控制意图。
- `Send` 用于运行时动态创建 Map-Reduce / Worker 任务。
- `ToolNode` 是预构建的工具执行 Node；当模型动态选择 Tool 时可以使用它，但确定性 Workflow 中也可以直接在普通 Node 内调用函数 / API。
- `InMemorySaver` / `MemorySaver` 只保存在内存中，适合学习与测试；生产应使用持久化 Checkpointer。
- `stream_mode="updates"` 适合观察每个 Node 实际产生的更新；当前官方 Streaming 文档也支持 `version="v2"` 的统一 StreamPart 结构。

当前 Vault **仍没有固定到一个精确的 `langgraph` Python package 版本号**。Part 3 示例代码按 2026-09-16 官方文档结构编写，但没有在仓库 CI 的锁定环境中执行，因此它的定位是“教学结构代码”，不是已经完成运行验收的工程交付。

## 业务案例来源边界

贯穿的“集团采购经营数据分析 Agent”是教学抽象，参考用户提供的企业数据 Agent、供应链分析和采购智能化材料中的常见业务形态：自然语言问数、跨源取数、异常下钻、报告生成、预警与决策辅助。

所有公司名、供应商名和数值都是**教学构造数据**，不是用户实习企业真实数据，也不代表用户提供材料中的真实指标。

用户提供的原始演示材料不复制进公开仓库，也不把其中企业名称、业务数据或效果数字作为 LangGraph 技术结论。
