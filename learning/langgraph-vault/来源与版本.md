## Part 2 中特别核对的运行行为

- Graph API 的基本组成是 State、Node、Edge；Node 返回 State Update，Reducer 决定字段如何合并。
- LangGraph 以 Super-step 推进；同一个 Super-step 的节点可以并行执行。
- `compile()` 负责把 Graph 定义转成可执行 Graph；`invoke()` / `stream()` 才真正运行任务。
- 配置 Checkpointer 后，Checkpoint 按 Super-step 边界保存；Thread 通过 `thread_id` 组织一系列状态快照。
- 同一 Super-step 内某个节点失败时，已经成功节点的 Pending Writes 可以被持久化，恢复时无需重新执行这些成功节点。
- InMemorySaver / MemorySaver 只在内存中保存，进程重启后不能作为生产持久化方案。

## 业务案例来源边界

贯穿的“集团采购经营数据分析 Agent”是教学抽象，参考用户提供的企业数据 Agent、供应链分析和采购智能化材料中的常见业务形态：自然语言问数、跨源取数、异常下钻、报告生成、预警与决策辅助。

Part 2 中所有公司名、供应商名和数值都是**教学构造数据**，不是用户实习企业真实数据，也不代表用户提供材料中的真实指标。

用户提供的原始演示材料不复制进公开仓库，也不把其中企业名称、业务数据或效果数字作为 LangGraph 技术结论。技术行为仍只由 LangGraph 官方资料支撑。
