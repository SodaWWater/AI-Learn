# Part 4｜不再背知识点，而是沿真实追问把知识讲深

Part 1～3 已经解决“有什么、怎么跑、怎么写”。Part 4 的目标不是重新把 State、Node、Checkpoint 单独讲一遍，而是从真实市场题池里挑出主问题，再沿面试官最自然的追问一路向下。

题目骨架来自 [[../../面试题池/05-20条深度主链|20 条深度主链]]，原始 69 道候选题仍完整保留在 [[../../面试题池/01-高价值题目池|高价值题目池]]。

## 每一条主链怎么读

每篇都固定包含：

```text
面试主问题
→ 可直接用于面试的回答
→ 先建立整体图
→ 逐层拆机制与因果关系
→ 放入采购经营分析 Agent 看真实数据/流程
→ 关键代码与工程边界
→ 追问树逐题展开
→ 常见错误答案
→ 生产环境进一步问题
→ 官方来源
```

这意味着你可以先读“面试回答”，知道该怎么说；再读后面的深讲，理解为什么这样说。

## 第一批完成后的目标

读完 M01～M03，你应该能回答三个非常基础、但会持续被追问的问题：

```text
为什么选 LangGraph？
      ↓
它在真实系统里到底负责哪一段？
      ↓
为什么这个系统要拆成这些 Node / Subgraph / Agent？
```

如果这三问答不扎实，后面的 State、Checkpoint、Retry、安全权限都会变成零散机制；如果这三问扎实，后续问题都会有明确的架构位置。
