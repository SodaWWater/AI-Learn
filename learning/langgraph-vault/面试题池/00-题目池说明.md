# LangGraph 面试题池说明

这套题池先回答：2025～2026 公开面经、候选人回忆、LangGraph 专项题库和当前官方文档里，真正值得准备的 LangGraph / Agent 工程问题有哪些？

第一阶段已经得到 [[01-高价值题目池|69 道高价值候选题]]。第二阶段不是删题，而是把 69 道题组织成 [[05-20条深度主链|20 条主问题 + 追问树]]，并用 [[06-69题覆盖映射]] 保证原题全部保留。

## “压缩”到底是什么意思

```text
错误理解：69 道 → 删除很多 → 剩 20 道

当前做法：69 道原题全部保留
        ↓
识别它们之间的知识依赖和面试追问关系
        ↓
形成 20 个主问题
        ↓
每个主问题下面挂多层追问
        ↓
69 道题成为追问树中的叶子或中间节点
```

这样做是为了形成深度，而不是减少覆盖面。

## 题目优先级

### P0：核心高价值

满足以下一个或多个条件：

- 在真实/较可信面经中直接出现；
- 在多个独立来源中反复出现；
- 是其他生产题的前置机制，例如 State、Checkpoint、Retry、Tool 权限；
- 与 AI Agent 开发岗的项目深挖和系统设计高度相关。

### P1：高级高价值

通常是：

- 真实面试中出现次数较少，但一旦被追问能明显区分工程深度；
- 偏二面 / 系统设计 / 生产级；
- 依赖 P0 的机制基础。

## 证据强度

| 标记 | 含义 |
|---|---|
| E3 | 至少有第一人称/verified 面试证据，并在其他独立来源再次出现或得到较强交叉印证 |
| E2 | 有一条第一人称/verified 证据，或多条带岗位/日期的二次面经共同出现 |
| E1 | 主要来自高质量专项题库、生产实践或官方能力边界；作为重要补充，但不声称是高频真题 |

证据强度不是题目难度。

## 去重与组链原则

不按句子表面去重，而按“面试官真正想考什么”和“下一步自然会追问什么”组织。

例如：

```text
为什么用 LangGraph？
→ 为什么不用 Python while-loop？
→ 为什么不用高层 create_agent？
→ 为什么不用自研 Runtime？
→ LangGraph 有什么缺点？
```

它们不是五个互不相关的知识点，而是一条技术选型深挖链。

而下面两题虽然都出现“恢复”，仍然必须分开：

```text
Checkpoint 如何恢复？
外部 Tool 已成功但响应丢失怎么办？
```

前者主要是 LangGraph durable execution；后者已经进入外部副作用、幂等和 reconciliation。

## 当前纳入范围

- LangGraph 框架定位与项目选型；
- State / Reducer / Runtime / Control Flow；
- Checkpoint / Thread / Store / HITL；
- Tool Calling、Node、LLM 的执行边界；
- 并发、重试、恢复、长链路稳定性；
- Streaming、Observability、Evaluation；
- Security、Permission、Multi-tenancy、Prompt Injection；
- Subgraph / Multi-Agent；
- 生产级 Agent 系统设计。

## 版本规则

题目来源可以是旧版本，但后续答案必须按当前官方版本重写。

2026-09-16 当前官方文档需要特别注意：

- LangGraph `create_react_agent` 已弃用，当前高层 Agent 推荐 `langchain.agents.create_agent`；
- `MessageGraph` 已弃用，使用 `StateGraph` + `messages`；
- LangGraph v1 的 State / Node / Edge / Runtime 核心模型仍然稳定；
- 旧题库里若仍把 `create_react_agent` 当当前首选，只保留其历史/迁移价值，不照抄答案。
