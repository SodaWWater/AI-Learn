# LangGraph 面试题池说明

这一步**不写答案，也不按我自己的想象造题**。目标是先回答：2025～2026 公开面经、候选人回忆、LangGraph 专项题库和当前官方文档里，真正值得准备的 LangGraph / Agent 工程问题有哪些？

题目池完成后，再基于证据强度、岗位相关性和知识依赖关系决定 Part 4 / Part 5 的学习顺序。

## 本次题目池的来源层级

| 层级 | 含义 | 用法 |
|---|---|---|
| A：第一人称 / 已验证面试经历 | 候选人明确描述自己被问过，或平台标记为 verified experience | 最重要的“市场真实提问”证据 |
| B：带公司/岗位/日期的面经整理 | 可能是二次整理或多场汇总，但保留了岗位与时间信息 | 判断重复主题和国内 Agent 岗关注点 |
| C：LangGraph 专项题库 / 面试指南 | 不证明某公司真实问过，但覆盖面广 | 用来补漏，尤其是生产、HITL、并发、安全等 |
| O：LangGraph / LangChain 官方文档 | 不是面试题来源 | 只负责核验当前 API、概念和版本状态，防止题库答案过时 |

完整登记见 [[02-来源登记与搜索记录]]。

## 题目优先级

### P0：核心高价值

满足以下一个或多个条件：

- 在真实/较可信面经中直接出现；
- 在多个独立来源中反复出现；
- 是其他生产题的前置机制，例如 State、Checkpoint、Retry、Tool 权限；
- 与 AI Agent 开发岗的项目深挖和系统设计高度相关。

P0 不是“最简单”，而是**最值得先准备**。

### P1：高级高价值

通常是：

- 真实面试中出现次数较少，但一旦被追问能明显区分工程深度；
- 偏二面 / 系统设计 / 生产级；
- 依赖 P0 的机制基础。

## 证据强度

| 标记 | 含义 |
|---|---|
| E3 | 至少有第一人称/verified 面试证据，并在其他独立来源再次出现或得到较强交叉印证 |
| E2 | 有一条第一人称/verified 证据，或多条带岗位/日期的二次面经共同出现 |
| E1 | 主要来自高质量专项题库、生产实践或官方能力边界；作为重要补充，但不声称是高频真题 |

**证据强度不是题目难度。** 安全、Schema Migration 等非常重要的生产题，公开一手面经可能较少，因此可能是 `P1 / E1`。

## 去重原则

不按句子表面去重，而按“面试官真正想考什么”去重。

例如下面几种表述会合并到同一主题：

```text
为什么用 LangGraph？
LangGraph 和 LangChain 有什么区别？
为什么不用脚本硬编码？
为什么不用别的 Agent 框架？
```

它们不能全部合成一道题，因为背后的考点分别是：框架定位、Agent/Workflow 边界、显式状态与恢复、框架选型与迁移成本。

反过来，`Checkpoint 如何恢复` 与 `外部 Tool 已成功但响应丢失怎么办` 也不能因为都出现“恢复”就合并：后者实际上在考外部副作用、幂等与对账。

## 本次纳入范围

纳入：

- LangGraph 框架定位与项目选型；
- State / Reducer / Runtime / Control Flow；
- Checkpoint / Thread / Store / HITL；
- Tool Calling、Node、LLM 的执行边界；
- 并发、重试、恢复、长链路稳定性；
- Streaming、Observability、Evaluation；
- Security、Permission、Multi-tenancy、Prompt Injection；
- Subgraph / Multi-Agent；
- 生产级 Agent 系统设计。

暂不纳入：

- 与 LangGraph 无直接关系的 Java 八股、DSA；
- 纯 RAG 算法题，除非它被问成 Agent 工作流中的一个节点或失败边界；
- 纯模型训练 / DPO / GRPO；
- 没有来源支持、仅为了“显得高级”而虚构的问题。

## 版本规则

题目来源可以是旧版本，但**后续答案必须按当前官方版本重写**。

2026-09-16 当前官方文档需要特别注意：

- LangGraph `create_react_agent` 已弃用，当前高层 Agent 推荐 `langchain.agents.create_agent`；
- `MessageGraph` 已弃用，使用 `StateGraph` + `messages`；
- LangGraph v1 的 State / Node / Edge / Runtime 核心模型仍然稳定；
- 旧题库里若仍把 `create_react_agent` 当当前首选，只保留其历史/迁移价值，不照抄答案。

参见 [[来源与版本]] 与 [[03-题目去重与市场观察]]。
