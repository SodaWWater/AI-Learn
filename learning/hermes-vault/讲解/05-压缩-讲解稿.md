# 第五章讲解稿

配合 `chapters/05-context-compression-session-rotation-recovery.md` 使用。所有实现结论绑定官方提交 `f97a410`。课程仓库只提供讲法和对照，不覆盖源码。

## 0. 这一章要建立的一句话

压缩不是删字，是一次**有门槛、有候选、有提交点、失败不制造新事实**的事务。Prompt cache 把“中途改历史”视为昂贵操作；AGENTS.md 写明：**唯一合法改上下文的例外就是 compression**。

面试可以说：Hermes 把 compaction 当成 cache-breaking 的受控事务，而不是上下文窗口的字符串截断。

## 1. 先把三个容易混的东西拆开

| 名字 | 源码 | 做什么 | 默认 |
|---|---|---|---|
| 工具结果回收 | `ContextCompressor.prune_tool_results_only` | 不去摘要模型，把旧 tool 结果去重/压成一行 | 过 `proactive_prune_tokens` 才提交 |
| 语义压缩 | `ContextCompressor.compress` + `compress_context` | 保 head/tail，把 middle 交给辅助模型写 checkpoint | 主路径；默认 `in_place=True` |
| Micro-compaction | `agent/micro_compaction.py::_micro_compact` | 把旧 user/assistant 轮次滚进一条 summary marker | **默认关闭**，因为每次改前缀都会打 cache |

第五章正文里如果把前一项叫做 Micro-compaction，那是术语撞车。官方 `micro_compaction.py:199` 的入口注释写得很清楚：它从 `finalize_turn()` 进来，并用 `archive_and_compact` 同步 DB，避免 append-only flush 在 resume 时双载。

课程 `13-pi-agent/05-compaction.md` 讲的是 Pi 的 compaction，不要和 Hermes 混读。

## 2. 双层压缩，不要只记 50%

官方文档 `website/docs/developer-guide/context-compression-and-caching.md`：

```text
Gateway Session Hygiene   85%   进 agent 之前的安全网（gateway/run_turn.py）
Agent ContextCompressor   50%   循环内主压缩（可配；真实/锚定 token）
```

Gateway 阈值故意更高：曾经设成 50% 会让长 Telegram/Discord 会话每轮都压。Agent 层才是日常管理；Gateway 是“隔夜堆起来、agent 自己没赶上”的网。

配置默认（同一份文档，已在 `context_compressor.py` 对上）：

- `compression.threshold = 0.50`
- `compression.in_place = true`（缺省必须是原地，不能默认为轮换）
- `tail_mode = lean`：尾部约 `2.5% × window`（10K 地板、25K 帽），连续性主要靠摘要 + 机械锚点 + `session_search`
- `protect_last_n = 20`，`protect_first_n = 3`（硬编码默认；**第一次压缩之后 head 保护会 decay 到 0**，见 `_effective_protect_first_n`）

## 3. 什么时候压：读数 →  defer → 闸门 → 预检

### 3.1 读数有三层

`turn_context.py:37 _preflight_request_tokens`：

1. `anchored_context_tokens`：上次 Provider usage + 之后追加消息的 delta（优先）
2. `estimate_native_responses_preflight_tokens`：Codex/Responses 原生估算
3. `estimate_request_tokens_rough(messages, system_prompt, tools)`：把 system / messages / tools 一起估

粗估虚高不等于请求会失败。`should_defer_preflight_to_real_usage`（`context_compressor.py:2449`）规定：没有锚点的整段 rough 超阈值，**先等一次真实 usage**。压缩刚结束、latch 还在，也要等。Provider 已证明自己不回 usage 时不再空等。Overflow 错误走反应式恢复，不靠粗估“看起来已经爆了”。

### 3.2 `should_compress_info` 只管“现在能不能试”

```python
# context_compressor.py:2472
tokens < threshold           → False
_automatic_compression_blocked → False + cooldown / structural_backoff / ineffective
else                         → True
```

断路器：两次无效压实 **或** 两次 fallback 连续 → tripped。恢复用 **wall clock** 持久 deadline，不是 monotonic：Gateway 每轮重建 `AIAgent`，单调时钟会让 blocked session 永远挣不到 probe。

### 3.3 预检 Gate 在 `should_compress` 之外还看什么

`turn_preflight.py:run_preflight_compression` 的实际合取：

- `compression_enabled` 且 `len(messages) > 1` 且尝试次数未耗尽
- 不是 review fork 的第一次请求
- 未被 `_preflight_compression_blocked`（除非 provider-proven overflow）
- `defer_preflight` 为假（除非 overflow）
- 没有 summary-failure cooldown
- `compressor.should_compress(request_pressure_tokens)`

通过后：llamacpp 监督地址可先 `_maybe_grow_local_window`；再调用 `agent._compress_context`。

**锁不在这个 if 里。** 锁是 `compress_context` 里拿的 lease。拿不到或被挡住，函数返回原 `messages`；预检看到 `compression_skipped_due_to_lock` / `compression_blocked_transiently` 后 **退还 attempt**，不把“暂时 defer”当成“压不动”。

压完没碰到 Provider：退还 `api_call_count` 和 budget，然后 `conversation_history_after_compression` 重绑历史，再进下一轮预检。

## 4. 便宜路径：`prune_tool_results_only`

口播：工具输出通常比用户话大一个数量级。先做可预测回收，再考虑请摘要模型。

`_prune_old_tool_results` 顺序（`context_compressor.py:2737`）：

1. 浅拷贝，建 `tool_call_id` 映射
2. 去重：最新全文，旧的换成 `[Duplicate tool output — same content as a more recent call]`（无损，tail 也可做）
3. 收集 `protected_skills`：刚加载且仍被 tail 引用的 `skill_view` 先留全文
4. 旧 tool 结果压成一行（过 `min_prune_chars`）
5. 旧 `tool_calls.arguments` 在解析后的 JSON 内截断，保证仍是合法 JSON
6. **Pass 3.5**：除最近 `_MAX_KEEP_TOOL_IMAGES = 3` 帧外，回收图片 payload
7. 若 tail 自己超软预算，`_pressure_demote_tail`

提交闸门（`prune_tool_results_only:2841`）：低于 `proactive_prune_tokens` 直接返回原对象；回收量 < `proactive_prune_min_reclaim_tokens` 也不提交；没有 `archive_and_compact` 的 store 直接 no-op。返回契约是 **`result is not input` 才算真提交**。提交后 stamp `_db_persisted`，并设 rearm 水位，避免每轮都打 cache。

## 5. 昂贵路径：剪辑师 vs 制片人

这个比喻来自课程 `08-hermes-agent/01-memory/notebooks/5_compress.md`，分工是对的，**行号已经过期**。当前提交：

| 角色 | 文件 | 当前入口 |
|---|---|---|
| 剪辑师：怎么压 | `context_compressor.py` | `ContextCompressor` `:1660`，`should_compress` `:2468` |
| 制片人：压完怎么办 | `conversation_compression.py` | `compress_context` `:3543`，`_commit_compaction` `:3223` |

`compress_context` 关键顺序：

1. Codex app-server 走原生 compact，不走 Hermes 摘要
2. 自动路径过 breaker（`force=/compress` 清 cooldown；`bypass_cooldown` 只跳过 cooldown、不断路器）
3. 懒探测摘要模型可行性
4. `in_place = getattr(agent, "compression_in_place", True)` —— **缺省 True**
5. 拿 lease；父 session 已轮换则 adopt child
6. 调引擎 `compress()` 得到候选
7. `_candidate_rejected` 不过则原样返回
8. `_commit_compaction` 才碰 SessionDB
9. `_rebuild_system_prompt_at_boundary` + `conversation_history_after_compression`

课程讲稿仍写“默认轮转 child”，与当前默认相反。以源码为准。

## 6. 两套 Prompt，不要当成一套

课程 `04-prompt/catalog/03c_summarizer_runtime.md` 这张图值得留下：

```text
窗口将爆
  → A. 辅助模型 task="compression"
       preamble + first/iterate + Historical* 章节
       产出结构化摘要正文
  → B. 主模型
       SUMMARY_PREFIX + 正文 + END MARKER
       作为 user 消息插回 history
```

A 的设计点：用 checkpoint / source material 软措辞，避免 Azure/OpenAI filter；与用户同语言；密钥改 `[REDACTED]`；有日期时强制过去时，防止“还要给 John 发邮件”被主模型再执行一遍。

B 的护栏就是你在 compaction 摘要里看到的红字：`[CONTEXT COMPACTION — REFERENCE ONLY]`，只响应摘要**之后**的最新 user 消息。`Historical*` 前缀是为了防止主模型把旧 TODO 当成当前任务。

序列化给 A 看的文本（`_serialize_for_summary:2938`）实际标签是：

```text
[USER]: ...
[ASSISTANT]: ...
[Tool calls:
  read_file({"path":"deploy.sh"})
]
[TOOL RESULT call_xxx]: ...
```

不是 `[TOOL:read_file]`。每条正文 `_CONTENT_MAX=6000`，头 4000 + 尾 1500；参数 `_TOOL_ARGS_MAX=1500`。

摘要输出预算：`content_tokens * 0.20`，夹在 2000 与 `min(window*5%, 10000)` 之间。这是摘要模型的预算，不是主模型下一次请求的预算。

## 7. 候选检查：有文本 ≠ 成功

`_candidate_rejected:3136` 的顺序（四段，不是三段）：

1. `_last_compress_aborted` → 警告，不旋转
2. 语义无进展（`==` 或去掉 `_db_persisted` 后相等）→ 记 structural no-op backoff
3. 空 transcript → 拒绝，父 session 仍可 resume
4. attempt generation 被更新的尝试取代 → 丢弃晚到候选

另外还有反增长：rough(candidate) 不小于原轨迹就 salvage，再不行记 ineffective strike。成功定义是四件事同时成立：可继续、可发送、变小、可安全提交。

`CompressionCommitFence:366`：worker 线程杀不掉，所以用栅栏让“取消发生在 mutation 之前”或“已经开始的 commit 必须跑完”。Lease 丢了，晚到结果不能进 DB。

## 8. 提交之后必须刷新的边界

无论 in-place 还是 rotation：

- `_rebuild_system_prompt_at_boundary`：invalidate → 刷新 tools → 重建 stable/context/volatile
- `conversation_history_after_compression`：重绑下一次可见历史
- 清文件读 / `skill_view` 去重 generation
- 重置 usage anchor（压缩是锚点失效点之一）
- 通知 Context Engine / Memory / `session:compress`

Rotation 额外：flush 未持久化尾部到父 session → 关父、原子发布 child → 迁 `/goal` `/heartbeat` `/loop` 和标题。父 session 被用户明确结束后禁止发布。失败时父轨迹保持可恢复，子 session 不索引半成品。

崩溃语义：摘要中崩溃 = 无提交 = 下次从旧历史重判；提交后崩溃 = 依赖 DB 事务 + `_db_persisted` + 重启后 `conversation_history_after_compression`。
