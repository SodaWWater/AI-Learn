# JD 与个人经历映射

目标：把岗位要求、已有经历和知识缺口放到一张表里，避免面试准备时“技术学很多，但没有和岗位及个人经历连起来”。

## 1. 总体匹配关系

| JD 关键词        | 现有证明                                  | 当前判断           | 准备策略                                 |
| ------------- | ------------------------------------- | -------------- | ------------------------------------ |
| 理解大模型         | 已有 RAG、Agent、Prompt、LangGraph 学习与项目经验 | 有基础，但需补产品级模型认知 | 补 LLM 能力边界、RAG/Prompt/Fine-tuning 选型 |

## 2. 津药项目应该如何贴 JD

原始项目的核心不是“Excel 自动化”，而是：

```text
四个医药集团 ERP/SRM 数据与流程不一致
        ↓
梳理端到端业务流程
        ↓
确定自动化与人工确认边界
        ↓
统一数据模型 / 字段 / 业务口径
        ↓
把确定性计算封装为 Tool
        ↓
用 Prompt / Workflow 调度分析任务
        ↓
异常复核与最终结果交付
```

适合证明：

- 医疗/医药业务理解；
- 需求梳理和流程重构；
- 数据标准化；
- Prompt 与结构化输出；
- Tool 与 AI 的任务边界；
- 人机协同；
- AI 对企业流程效率的价值。

不适合强行证明：

- 金融风控；
- 复杂多轮对话；
- 隐私计算；
- 可信数据空间。

## 3. Health Agent 应该如何贴 JD

产品主线：

```text
个人健康数据分散、用户难以持续理解变化
        ↓
统一账户下记录与指标
        ↓
趋势 / 报告 / 问答三类体验
        ↓
LangGraph 组织 Agent 工作流
        ↓
Tool 获取确定性数据
        ↓
RAG 提供外部知识与证据
        ↓
LLM 做理解、解释和生成
        ↓
Citation / Refusal / 权限 / 人工确认控制风险
```

适合证明：

- 医疗健康 AI 产品；
- Agent 架构；
- Tool Calling；
- RAG；
- Citation / No-answer；
- 智能报告；
- 数据解读；
- 多轮对话基础；
- 权限、隐私、来源追踪和产品风险边界。

## 4. 面试时的统一个人定位

不要把自己说成“后端开发转产品”，也不要说成“我只是比较喜欢沟通”。

更准确的定位是：

> 我是软件工程背景，过去的两段核心经历都在做“业务场景如何被 AI 产品化”的问题。一段是在真实医药企业里，把多系统、多口径的数据分析流程重新梳理并设计自动化边界；另一段是自己做健康管理 Agent，把大模型、RAG、Tool Calling、报告和权限治理组合成一个完整产品。我希望继续做的是连接业务、数据和 AI 技术的产品工作。

## 5. 后续每章都必须回答的映射问题

每学一个知识点，都要求回答：

1. 这个能力在 JD 里为什么出现？
2. 平安金融 / 医疗产品里可能怎么使用？
3. 津药项目能不能证明？如果能，证明哪一段？
4. Health Agent 能不能证明？如果能，证明哪一段？
5. 如果不能证明，应该以“学习后的迁移方案”还是“真实经历”来回答？

只有完成这五问，才算这个知识点真的和面试准备完成连接。
