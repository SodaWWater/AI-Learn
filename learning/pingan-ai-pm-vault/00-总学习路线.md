# 总学习路线

目标：在短周期内，围绕深圳平安科技 AI / 大模型产品经理 JD，建立“技术理解 → 场景设计 → 数据可信 → 产品落地 → 面试表达”的完整防守体系。

## Part 1：先从熟悉的技术侧开始

### 1. 大模型基础与智能体架构

必须掌握：

- 大语言模型（Large Language Model，LLM）是什么，擅长和不擅长什么；
- Token、Context Window、Inference、Temperature 的产品含义；
- RAG、Prompt、Fine-tuning 的使用边界；
- Agent、Workflow、Tool、State、Memory、Planning、Guardrail 的关系；
- Agent 与固定 Workflow 的区别；
- 为什么金融/医疗场景通常需要“受控 Agent”而不是完全自由自治。

经历映射：Personal Health Agent、LangGraph 学习经历。

### 2. Prompt、结构化输出与 Tool Calling

必须掌握：

- System / User Prompt 分工；
- Instruction、Context、Constraint、Example；
- Structured Output 与 JSON Schema；
- 参数校验、失败重试与下游系统消费；
- Tool Calling 的选择、调用、返回、权限和安全边界；
- 确定性计算为什么应该交给 Tool，而不是让 LLM 心算。

经历映射：津药采购 Agent 的结构化 Prompt、Schema、确定性 Tool；Health Agent 的 Tool Governance。

### 3. 长文本、多轮对话、RAG 与幻觉抑制

必须掌握：

- 长文本为什么不能只靠“塞进 Context Window”；
- Chunking、RAG、Map-Reduce、摘要与分层检索；
- 多轮会话中的 Session、State、History、Memory；
- 上下文裁剪、总结、长期记忆与污染问题；
- 幻觉的类型与治理：Grounding、Citation、Tool、Validator、Refusal、HITL、Eval；
- AI 产品评估：正确性、任务成功率、Groundedness、Latency、Cost。

经历映射：Health Agent 的 RAG、Citation、No-answer、持久化会话、报告生成。

---

## Part 2：进入业务场景应用

### 4. 数据解读产品

学习目标：

- 如何把结构化指标转化为用户可理解的结论；
- 指标计算、异常识别、趋势分析、LLM 解读如何分工；
- 如何保证结论有数据依据；
- 数据解读产品如何设计追问和解释链。

经历映射：健康指标解读、采购经营数据分析。

### 5. 智能报告产品

学习目标：

- 报告的数据源、指标层、知识层、生成层、校验层；
- 报告模板、结构化输出、Citation、人工确认；
- 批处理与交互式任务的差异；
- 如何定义报告质量指标。

经历映射：周期健康报告、采购分析结果交付。

### 6. 信贷风险产品

学习目标：

- 信贷业务基本流程；
- 传统规则 / 风险模型与 LLM 的角色分工；
- 非结构化材料理解、风险解释、报告辅助；
- 高风险决策中的人工审批、解释性、审计与模型边界。

定位：专项补课，不包装为做过。

### 7. 潜客推荐产品

学习目标：

- 客户画像、标签、候选生成、排序、转化；
- 推荐模型 / 规则系统 / LLM 的分工；
- Next Best Action、营销辅助、个性化文案；
- 用户反馈闭环与效果评估。

定位：专项补课，不包装为做过。

### 8. 金融 / 医疗 AI 创新应用

学习目标：

- 从业务痛点判断是否需要 LLM / Agent；
- 找到“确定性系统 + AI”组合，而不是为了 AI 而 AI；
- 识别高风险、高价值、强数据依赖场景；
- 能提出至少 2 个金融和 2 个医疗方向的合理方案。

## Part 3：补齐数据可信与产品落地

### 9. 可信数据空间

必须掌握：

- 为什么跨机构数据不能简单集中共享；
- 身份可信、授权、使用控制、审计、追溯；
- 数据“可用不可见”的含义；
- 可信数据空间与普通数据库、数据中台、数据湖的区别；
- 金融和医疗为什么天然需要这一能力。

### 10. 隐私计算技术栈

必须掌握产品级理解：

- 联邦学习（Federated Learning，FL）；
- 多方安全计算（Secure Multi-party Computation，MPC）；
- 可信执行环境（Trusted Execution Environment，TEE）；
- 同态加密（Homomorphic Encryption，HE）；
- 隐私集合求交（Private Set Intersection，PSI）。

不要求算法推导，但要能回答：解决什么问题、成本是什么、什么场景选它。

### 11. 金融数据合规

必须掌握：

- 数据最小必要；
- 用户授权与用途限制；
- 数据分类分级；
- 权限与最小权限；
- 敏感信息脱敏；
- 日志、审计、可追溯；
- 数据保留与删除；
- LLM 输入输出泄露风险；
- 高风险业务的人机协同和责任边界。

### 12. AI PRD 与 0→1 产品落地

必须掌握：

- 业务目标；
- 用户与角色；
- 原流程与痛点；
- AI 必要性判断；
- 数据需求；
- 产品流程；
- 模型 / Agent / Tool 边界；
- Prompt / RAG / Tool 设计；
- 合规与风险；
- Fallback / HITL；
- MVP；
- Eval；
- 成本和性能；
- 试点、推广和迭代。

## Part 4：最终面试防守

最后不按知识点背答案，而是形成以下几条连续追问链：

1. 为什么做 AI 产品经理 → 你的技术背景如何形成优势？
2. 讲津药项目 → 需求、流程、AI 方案、价值、复盘。
3. 讲 Health Agent → 为什么是 Agent、RAG、Tool、幻觉、权限、报告。
4. 设计金融智能报告产品。
5. 设计信贷风险 AI 产品。
6. 设计潜客推荐 AI 产品。
7. 解释可信数据空间、隐私计算、金融合规。
8. 从 0 到 1 写一款 AI 产品 PRD 并推动落地。

## 时间优先级

在面试前时间紧张的情况下：

- **最高优先级**：Part 1 技术侧 + 智能报告 / 数据解读；
- **第二优先级**：可信数据空间 + 隐私计算 + 金融合规；
- **第三优先级**：信贷风险 + 潜客推荐；
- **最后收口**：PRD、0→1 产品设计与模拟面试。
