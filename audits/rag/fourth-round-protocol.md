# 检索增强生成（Retrieval-Augmented Generation，RAG）第四轮独立补漏协议

版本：2026-09-03

适用工作项：`WP-P2-002`

> 执行状态：`paused / historical protocol`
> 用户已在三轮 18/18 完成后决定暂停继续向外搜索。数据摄取（Data Ingestion）、文档解析（Document Parsing）、数据治理（Data Governance）和文本切分（Chunking）的第四轮结果作为 4/18 历史检查点保留；不得继续其余 14 个节点，除非用户再次明确授权。当前任务以 [`docs/LOCAL_AGENT_HANDOFF.md`](../../docs/LOCAL_AGENT_HANDOFF.md) 和 [`manual-review-status.json`](manual-review-status.json) 为准。

## 1. 目标

第四轮不是重复第三轮检索，而是用不同查询表达、不同来源入口和反例驱动方式验证每个节点是否仍存在未登记的知识、工程问题、解决方案、实现、评估、安全或公开面试题类型。

## 2. 独立性规则

每个节点至少满足以下四项中的三项：

1. 不复用上一轮完整检索式，改用失败现象、反例、协议字段或基准名称反向搜索；
2. 至少引入一个上一轮未使用的来源族，例如标准、正式规范、固定源码提交、原始论文、官方限制页、公开一手面经；
3. 至少进行一次冲突检索，主动寻找反对既有结论、能力限制、失败复现或版本变更；
4. 至少进行一次跨节点检索，验证当前问题是否错误地只归属于单一节点。

仅更换关键词顺序、转载同一结论或同一来源的二次解读，不计作独立轮次证据。

## 3. 节点验收步骤

1. 读取该节点前三轮日志、来源和未验证假设；
2. 建立本轮查询族和候选来源表；
3. 只把可定位、可复核的来源写入正式来源表；
4. 对候选信息执行“完全重复、扩展、冲突、新类型”分类；
5. 只过滤语义和条件均完全相同的重复项；条件、版本、失败模式、实现边界或评估方式不同则保留；
6. 更新公开问题时保留原始 URL（统一资源定位符）、题目定位和来源等级，不把论文问题改写成面试真题；
7. 完成九类覆盖检查、冲突记录和下一轮动作；
8. 执行仓库校验并保存 GitHub 检查点。

## 4. 饱和状态机

| 本轮结果 | 计数变化 | 状态 |
|---|---|---|
| 出现任一新知识或问题类型 | 重置为 0 | `round_complete` |
| 无新类型，但实现、来源或冲突前置项未闭合 | 最多记 1，且不可饱和 | `round_complete_with_gap` |
| 无新类型且所有前置项闭合 | 加 1 | `round_complete` |
| 连续两轮无新类型且所有前置项闭合 | 保持 2 并复核 | `coverage_saturated` |

“来源很多”“已检索三轮”或“九类表均为 covered”均不能替代上述状态机。

## 5. 第四轮优先缺口

| 优先级 | 缺口 | 重点节点 |
|---|---|---|
| P0 | 公开第一人称题目不足，尤其 Deep Research（深度研究）、Result Fusion（结果融合）和 Reranking（重排） | 高级、融合、重排 |
| P0 | Trace Schema（追踪模式）、Evaluation Manifest（评估清单）和 Exercise Manifest（演练清单）缺少可执行验证 | 评估、生产治理、高级 |
| P0 | 多模态间接注入的正文、图片、Metadata（元数据）、网页载体和 Tool Return（工具返回）尚未形成统一攻击矩阵 | 解析、检索、上下文、高级、治理 |
| P1 | 当前官方 API（应用程序接口）、模型和数据库文档的版本迁移与能力冲突需再核验 | 存储、检索、重排、生成、引用 |
| P1 | 中文、长文、表格、时间、冲突、无答案和权限样本的独立评测证据不足 | 全链路 |
| P1 | 查询改写、路由、融合和停止条件对后续节点的误差传播缺少统一可回放实验 | 查询到高级路线 |

## 6. 第四轮输出

- 18 份 `r4` 节点检索日志；
- 更新后的来源表和公开问题表；
- 每节点新增类型数、冲突数、未闭合前置项和连续无新增计数；
- 机器可读的未闭合缺口清单；
- 第四轮检查点和第五轮决策：继续补漏，或对满足条件的节点启动第二个连续无新增验证轮次。
